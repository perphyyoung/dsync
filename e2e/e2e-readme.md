# e2e 测试范围

每个文件对应一类场景。两位数字前缀只表示阅读顺序，与执行顺序无关——Playwright 并行跑。

| 文件                        | 覆盖范围                             |
| --------------------------- | ------------------------------------ |
| `01-app-shell.spec.ts`      | 窗口骨架与菜单                       |
| `02-scan-and-align.spec.ts` | 扫描与结构对齐执行                   |
| `03-recent-pairs.spec.ts`   | 最近目录对落盘与重启回填             |
| `04-soft-delete.spec.ts`    | 右键软删除、回收站可见、重扫后消失   |
| `05-scan-settings.spec.ts`  | 扫描设置页开关、条件共享、缺目录告警 |
| `06-preview-stats.spec.ts`  | 预览统计的批量开关                   |

## 01-app-shell.spec.ts

验证启动骨架，不涉及任何文件操作：

- 启动即打开扫描设置页：标题、目录空态、全部扫描条件（文件大小 / 目录层级 / 后缀 / 排除路径关键字 / 排除文件名关键字 / 修改日期范围 / 跳过隐藏文件）、`开始扫描`
- 红色 `强制重算` 复选框默认未选；勾选弹确认（`取消` 回退未选 / `启用` 保留勾选）
- 点「返回」进入主界面
- 目录表头空态：`未选择左侧目录`、`未选择右侧目录`
- 表头按钮：`打开` 两个（`更改` 只在扫描设置页）
- 文件列表三列表头：路径 / 修改日期 / 大小，左右各一组
- 非预览模式不渲染全选复选框（按 title「全选 / 取消全选」断言 count 为 0）
- 过滤行按钮：`扫描`；`强制重算` 已移入设置页（断言 count 为 0）
- 显示模式：`显示模式` 标签 + `全部` / `左侧` / `右侧` / `重复` / `占用` 五个按钮
- 状态栏入口：`向左同步预览`、`向右同步预览`

新增主界面常驻控件时，在这里补断言。

## 02-scan-and-align.spec.ts

验证「扫描 → 动作 → 落盘」这条主链路：

- 造两个临时目录：左侧 `deep/notes.md`、右侧 `notes.md`，内容相同
- 扫描结果应为一行 `moved`
- 手工构造一条 `move` 动作（界面现算逻辑的等价物），调用 `sync:execute`
- 执行后左侧文件出现在 `notes.md`，内容不变

`move` 动作在测试里写死，不经过界面；预览、勾选、确认这些界面层行为不在覆盖范围内。

## 03-recent-pairs.spec.ts

验证最近目录对的持久化与重启回填：

- 扫描成功后 `appData/dir-pairs.db` 的 `dir_pairs` 表应有一条记录
- 关闭应用、用同一个 `appData` 重启后，先点「返回」离开扫描设置页，表头显示上次的两个路径

新增与「启动回填」「最近列表」相关的行为时，在这里补断言。

## 04-soft-delete.spec.ts

三个用例，共用同一个实例与目录对。前两条覆盖无配对文件，第三条覆盖配对行。扫描统一走 `scanViaSettings`：在设置页直接点「开始扫描」，在主界面先点「扫描」进入设置页。

**右键软删除进回收站，重扫后不再出现**（无配对）

- 用 `app.evaluate` 替换 `dialog.showOpenDialog`，绕过系统目录选择
- 点「开始扫描」后列表出现 `a.md`
- 右键文件 →「软删除」→ 气泡确认「移入回收站」
- 原位置文件消失（轮询 5 秒）
- 点「回收站」能看到该条目，返回后重扫，列表不再出现

**软删除移除整行，还原后行恢复**（无配对）

- 补一个 `b.md`（与上例的 `a.md` 区分），扫描后右键软删除
- 对侧没有文件，整行应从列表消失，不留两侧都是「—」的占位行
- 回收站里按行定位「还原」，返回主界面后 `b.md` 行应重新出现，不需要重扫
- 没有对侧文件可配，还原后按增量新增一条单侧行

**配对行软删除只清一侧，还原后恢复配对**（有配对）

- 左侧 `deep/c.md` 与右侧 `c.md` 同内容，扫描后是一对 moved（不受「隐藏一致」影响）
- 软删除左侧后行保留，只清空左侧，状态变「仅右侧」
- 还原后应按对侧同哈希找回该行并恢复为 moved，而不是新增一条单侧行

这三条守着三个回归：主进程 `parseExecuteRequest` 过滤未知 `kind` 导致「点了没反应」；两侧皆空的行未移除；还原时未按哈希恢复配对。

## 05-scan-settings.spec.ts

验证扫描设置页的开关与条件共享：

- 启动自动打开设置页；点「返回」进主界面，再点「扫描」可重新打开
- 主界面勾选「文件大小」并填范围、改目录层级 → 设置页显示同一状态；设置页改回 → 返回主界面后过滤行同步
- 未选目录点「开始扫描」：告警条提示，停留在设置页
- 选目录 → 改条件 → 开始扫描成功 → 重启：目录对回填，条件随目录对恢复（数据在 `dir-pairs.db`）
- 左右目录互换：pairKey 排序归一化，仍命中同一组条件
- 删除目录对：当前使用中的不渲染 ×；其他行 × → 确认气泡 → 取消保留 / 确认后行消失
- 目录失效：删掉一侧目录后点「开始扫描」→ 告警「目录不存在」，仍停在设置页
- 修改日期范围三态互斥：默认不限；选「最近」天数启用并补 7；选「自定义」日期启用、天数禁用

## 06-preview-stats.spec.ts

验证预览统计的批量开关：

- 向右同步预览：复制 2、软删除 1，统计复选框默认全选
- 行内显示修改日期，格式 `YYYY-MM-DD`
- 点击路径列头三态循环：默认 → 升序 → 降序 → 默认（箭头同步出现/消失，按行坐标断言顺序）
- 取消「复制」→ 复制计数 0，仅剩软删除那行勾选
- 再勾选 → 复制恢复 2，全部行恢复勾选

## 约定

- 用例一律 `import { test, expect } from "./fixtures"`：实例按 spec 文件复用，换文件时自动关旧实例并删数据目录
- 启动耗时不计入用例 timeout（slot fixture 自带 15s 预算）
- 需要「关闭再打开」时用 `slot.relaunch()`，不要自己 launch
- 测试数据建在 `slot.base` 下，随实例销毁自动清理，用例结束不需要手动 rm
- 用例标题与结果由 fixtures 自动写入 `ds.log`（`▶` / `✓ 通过` / `✗`）
- 共用函数在 `e2e-helper.ts`（`e2eEnv` / `makeWorkdir` / `launchApp`），日志在 `e2e-logger.ts`
- 用例覆盖范围变化后，同步更新本文件对应章节
